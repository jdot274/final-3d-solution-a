# final-3d-solution-a — Instanced Glass LED Volume

A fully dynamic, **engine-agnostic**, **instanced** glassy LED volume: real-time in the
browser, portable as baked 3D files, defined with open-standard materials — runnable
**outside UE5 or inside it**. One `config/scene.json` drives the live web editor, the
Blender bake, the USD/glTF exports, and the UE import.

## Structure (single source of truth → adapters)

```
config/
  scene.json            ← THE source of truth (instancing · motion · glass · LED)
  presets/*.json        ← named looks (calm_blue, electric_storm)
core/
  materials/
    glass_openpbr.mtlx  ← OpenPBR Surface 1.39 (UE Substrate / Arnold / USD)
    glass_led.mtlx  neural_glass.mtlx
  shaders/deform.glsl   ← shared height-field deform (web + UE/WPO reference)
web/index.html          ← live editor (INSTANCED): InstancedMesh volume, GPU deform, glass, LED, video, JSON
web/cube.html           ← live editor (SINGLE BLOCK): one solid glass rectangle, triplanar LED, same stack
bridge/                 ← tested web→UE5 JSON pipeline (from the parallel build)
  param_server.py         zero-dep stdlib server, GET/PUT /params + live SSE
  control_panel.html      slider web editor
  ue5_remote_apply.py     pushes params into a UE5 Material Parameter Collection live
  wave_params_schema.json single source of truth for the bridge
blender/
  build_instanced.py    ← bake INSTANCED volume → GLB(EXT_mesh_gpu_instancing)+USD+USDZ+ABC
  build_glass_led.py    ← single hero slab bake
  build_led_volume.py   ← 3 driver variants (waves / heightmap / video)
  addon_param_server.py ← Blender add-on + live HTTP param server (localhost:7474)
  build_voxel_wave.py  build_neural_wave_asset.py  bake_alembic_direct.py  render_*.py
assets/
  hero/      GlassLED_Slab.{glb,usdz,abc,blend}
  voxel/     voxel_wave.glb  neural_wave_animated.{glb,abc}  neural_wave.glb
  variants/  LEDVolume_{Waves,Heightmap,Video}.{glb,usdz,abc}
  instanced/ glass_led_volume.{glb,usd,usdz,abc}   (generated by build_instanced.py)
  previews/  *.gif  *.png
unreal/
  build_ue_production.py  ← BUILDS the UE leg: MPC_GlassLED + M_GlassLED (WPO deform) +
                            BP_GlassLEDVolume (InstancedStaticMesh, 72-cube glass volume)
  ue_preview.png          rendered proof from the editor viewport
  INTERCHANGE.md          UE5 import, OpenPBR→Substrate, ISM/Nanite/Niagara instancing
assets/textures/        ← wave_heightmap / normalmap / flipbook (regenerated from math)
```

## Quick start

**Live editor (most dynamic):**
```bash
cd web && python -m http.server 8791   # → http://localhost:8791
```
Panel (top-right): edit **instancing** (countX·Y·Z, spacing, phase/hue spread), **motion**
(softbody/waves/heightmap/video), **glass** (OpenPBR-style: transmission, IOR, iridescence,
clearcoat, attenuation), **LED**. Drag-drop a video → drives the emissive. **Export scene.json**.

**Bake the instanced volume:**
```bash
blender --background --python blender/build_instanced.py    # reads config/scene.json
```

**Into Unreal:** see [`unreal/INTERCHANGE.md`](unreal/INTERCHANGE.md) — same `scene.json`,
OpenPBR→Substrate, ISM/Nanite/Niagara instancing.

## Instancing — all three targets, one config
| Target | Mechanism |
|---|---|
| Web (real-time) | `THREE.InstancedMesh` + per-instance `aPhase`/color, shared GPU deform shader |
| glTF | `EXT_mesh_gpu_instancing` (linked-duplicate export) |
| USD / USDZ | instanceable references (`use_instancing`) |
| UE5 | ISM / HISM · Nanite+WPO · Niagara mesh renderer |

Per-instance **phase** (so the volume shimmers, not marches in lockstep) is live in web/UE;
baked files share one animation per instance — which is what keeps instancing cheap.

## Open standards = no engine lock-in
glTF 2.0 · OpenUSD · **OpenPBR / MaterialX 1.39** · Alembic. The same mesh + material move
between browser, DCC tools, and Unreal with no re-authoring.
